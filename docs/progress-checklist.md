### Phase 1 findings that need action later

- [ ] The test command cannot run at all. It points at a bootstrap path that does not exist in this installation layout; the real one ships inside the dependency directory. Fixing the path is a small change.
- [ ] The baseline has no PHP test classes. One test configuration covers a directory holding only browser scripts, and the other covers three directories that do not exist. All automated coverage for this fork must be created from scratch.
- [ ] The repository's own test container definition is broken. It reuses a database definition that depends on a service the test file does not define.
- [ ] The development container definition mounts a database seed file that is generated by the asset build and is excluded from Git. The asset build must be run before that container will start correctly. This is a documentation gap, not a defect.
- [ ] The asset build fails at its first step unless Composer is installed on the build host, because that step shells out to Composer to regenerate the dependency licence list. Every other asset step runs without Composer.
- [ ] The asset build rewrites a tracked view file by injecting the generated script and stylesheet tags into it. Anyone building locally will see that file reported as modified.
- [ ] The application container image does not install PHP dependencies and does not run the asset build. Only the test image installs dependencies. A production image built from this repository as-is will not run.
- [ ] The application requires the asset build to have run before it is served. Without it the settings page fails outright, because it reads a theme directory that only the build creates.
- [ ] The environment file must contain an encryption key, or be writable at first start so the application can generate one. Otherwise the sales register fails outright.
