### Phase 1 findings that need action later

- [ ] The baseline has no PHP unit tests. The PHPUnit configuration points at a directory that contains only browser test scripts, and the second PHPUnit configuration points at three directories that do not exist. Any automated test coverage for this fork must be created from scratch.
- [ ] The repository's own test container definition is broken. It reuses a database definition that depends on a service the test file does not define.
- [ ] The development container definition mounts a database seed file that is generated by the asset build and is excluded from Git. The asset build must be run before that container will start correctly. This is a documentation gap, not a defect.
- [ ] The asset build fails at its first step unless Composer is installed on the build host, because that step shells out to Composer to regenerate the dependency licence list. Every other asset step runs without Composer.
- [ ] The asset build rewrites a tracked view file by injecting the generated script and stylesheet tags into it. Anyone building locally will see that file reported as modified.
- [ ] The application container image does not install PHP dependencies. Only the test image does. A production image built from this repository as-is will not run.
